# Security checklist — status and evidence

Audit of 2026-11-01 against the 20-point list. **Done** means it is enforced in code and covered by a passing automated test, or checked by a script you can run again. **Your action** means it is outside the code: deployment and operations work only the university can do.

| # | Check | Status | How / evidence |
|---|---|---|---|
| 1 | No secret API keys in the frontend | Done | The web app has no `VITE_*` secrets or keys. Tokens are kept in memory and the session only (never `localStorage`). SSO client secrets and webhook/ERP/mail secrets are sealed server-side and never returned by any API. |
| 2 | `.env` out of Git and public folders | Done | `.gitignore` excludes `.env` and `.env.*` (only `.env.example`, which has no values, is tracked). `npm run security:secrets` fails if an env file is ever tracked. Vite serves only `apps/web/public` (model file, no secrets). |
| 3 | Scan Git history for leaked secrets | Done | `npm run security:secrets` scans every commit for private keys, AWS/GitHub/Slack/Google/OpenAI-style keys, connection strings with passwords and env-style secret assignments. History is clean today; its only matches are test fixtures. It was verified to catch planted secrets. Also add gitleaks to CI when CI exists. |
| 4 | Rotate exposed keys | Your action, if ever needed | Nothing was found exposed. Rotation is built in: JWT keys (`JWT_KID`, the JWKS endpoint), API keys (revoke and create in Administration), webhook secrets, and `APP_ENCRYPTION_KEY` (sealed `enc:` values). |
| 5 | Permissions checked on the server, every request | Done | Every route uses `requireUser` and `requirePermission`. Grants are re-read on every request (a revoked role works on the next call; `auth.test.ts`). `route-coverage.test.ts` checks that every non-public route refuses an anonymous caller with 401. |
| 6 | Never trust IDs, roles or prices from the frontend | Done | The user comes from the token and roles from the database (no role claims in JWTs). Marks, timestamps, question ids and check results are recomputed server-side. `security:probes` sends forged `isAdmin`, `tenantId` and `roles` fields and verifies they are ignored. The revaluation fee reference is labelled "typed by the student, unverified" for the COE (see 17). |
| 7 | Users cannot access each other's data | Done | Every tenant table has forced row-level security (`tenancy.test.ts`). Student routes filter by the caller. `security-checklist.test.ts` has student B try 15 routes on student A's attempt: every call is refused with 4xx, nothing of A's is returned or changed. Fixed: the revaluation status route now answers 404 for someone else's attempt instead of an empty 200. |
| 8 | Lock down the database and private storage | Done in code; your action in deployment | The app connects as `examos_app` (no superuser). **New:** the API refuses to start in production if its database role is a superuser or BYPASSRLS. Append-only tables refuse UPDATE/DELETE. Documents are served only through authorised routes. In deployment: private network for PostgreSQL/Redis, TLS, and a private, versioned storage bucket. |
| 9 | Admin actions protected even when called directly | Done | Admin routes are permission-checked on the server, not by hiding buttons (`route-coverage.test.ts` calls every route as a student and as anonymous). Maker-checker: nobody changes their own duties. The platform bootstrap key is refused in production. |
| 10 | Test login, logout, password reset | Done | Login lockout, uniform error for unknown e-mails, and refresh-reuse detection (`auth.test.ts`). **New:** sign-out kills the access and refresh tokens at once. An administrator's password reset (`POST /tenant/users/:id/password-reset`, a *Reset password* button) unlocks the account, signs it out everywhere and mails a single-use link; only the newest link works, and setting a password signs out every session again (`security-checklist.test.ts`, `admin.test.tsx`). Before this, a new password did not end existing sessions. |
| 11 | Rate-limit login, signup and costly calls | Done | Login: 20 per 5 min per IP and e-mail, plus account lockout. Activation: per IP. Platform login: 10 per 5 min. **New:** SSO start/callback per IP, and per-user caps on costly work: sandbox sample runs 20/min, reference checks 30 per 10 min, PDF rendering 30–60/min, script export 10 per 10 min, re-evaluation and similarity analysis 10 per 10 min each (`security-checklist.test.ts`). Limits live in Redis and fall back to in-process counters (never open) if Redis is down. |
| 12 | Usage caps on paid resources | Done | ExamOS calls no paid AI API. The costly resource is the code sandbox: sample runs are capped per question per student, plus the per-user rate cap; grading runs once per distinct program; reference checks are rate-capped. |
| 13 | Validate inputs on the server | Done | Every body goes through a Zod schema (`validateBody`). Answer blocks, canvas and code are validated by kind and size. NUL bytes in JSON and URLs are refused. JSON is capped at 5 MB. `route-coverage.test.ts` sends garbage to every route and expects 4xx, never 5xx. |
| 14 | Safe database queries | Done | Knex query builder with bound parameters throughout. The few raw fragments contain no user input (scanned: no interpolated `raw`/`whereRaw`). |
| 15 | User content cannot run scripts | Done | React escapes all text. The one `dangerouslySetInnerHTML` (drawings) comes from a generator that escapes text and forces numbers and named colours. `X-Content-Type-Options: nosniff`. Deployment CSP in `docs/deployment.md`. |
| 16 | Restrict upload types and sizes | Done | Photos: JPEG/PNG/WebP only, at most 2 MB, consent required. **New:** the bytes must really be that image type (an HTML/SVG file renamed `.png` is refused; `security-checklist.test.ts`). Code project files are text with per-file and total limits and safe relative paths. |
| 17 | Verify payments on the server | N/A, made explicit | ExamOS takes no payments. The revaluation "fee reference" is only what the student typed. **New:** the COE screen labels it unverified and asks them to confirm it against the university fee record before approving. If fees should be enforced, the ERP/payment system must confirm payment through the integration API (§11 decision). |
| 18 | Debug off; no secrets in errors or logs | Done | Errors are RFC 7807 problems with stable codes, never stack traces. Production refuses to start without real JWT and encryption keys. Front-end source maps are off. **New:** logs also redact cookies, `x-device-session`, judge tokens and webhook signatures, besides `Authorization` and `x-api-key`. Request bodies are never logged. |
| 19 | Back up and test restore | Scripts done; your action to schedule | **New:** `infrastructure/scripts/backup.sh` (compressed `pg_dump`, owner-only, checksum) and `infrastructure/scripts/restore-check.sh`, which restores into a scratch database and compares every table's row count with the source. Run 2026-11-01: 70 tables, identical counts, 23 migrations. Schedule daily backups off-server, enable point-in-time recovery on the managed database, version the document bucket, and run the restore check monthly. |
| 20 | Test with two accounts, then logged out | Done | `security-checklist.test.ts`: student B against student A's attempt, then the same 15 calls without signing in (all 401). `tenancy.test.ts`: tenant A's token on tenant B. `route-coverage.test.ts`: every route anonymous. |

Run all checks again with `npm run typecheck`, `npm test`, `npm test -w @examos/web`, `npm run security:secrets`, `npm run security:audit` and `npm run security:probes` (needs the demo server).
