# Interruption and misconduct case matrix

Design rule: **we cannot predict the student**, so every case is classified by *what the system can verify*, not by what it suspects. Technical interruptions are never a warning. Deliberate acts become evidence for a named human; only a confirmed decision counts toward the five-warning suspension. Column *Tested* names the automated test that proves the behaviour.

| # | Scenario | What the system does | What the student sees | What the proctor / Exam Section sees | Counts as a warning? | Tested |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | Wi-Fi drops for 20 s | Client keeps typing into the local draft queue; saves resume with the same `clientOperationId`s (duplicates return the same receipt) | "Syncing…" then "Saved to server" | Nothing | No | exam-flow: duplicate op returns same receipt |
| 2 | Student switches Wi-Fi → hotspot (new IP) | Session is not bound to IP; the heartbeat logs `network.address_changed` as context | Nothing | Timeline entry only | No | recovery: reconnect from another address |
| 3 | Network down > 90 s | Heartbeat sweep moves the attempt to **RECOVERY_PENDING**; answers preserved; clock keeps running (Controller policy may extend) | "Connection lost — your answers are safe. Reconnecting…" | Candidate shows *Connection lost* | No (no incident is created) | recovery: sweep → RECOVERY_PENDING, no incidents |
| 4 | Student reconnects | `reconnect` returns the attempt to ACTIVE with the server revision of every answer so the client can rebase | Editor resumes; unsynced local changes are replayed | Timeline: `attempt.reconnected` | No | recovery |
| 5 | Browser crash / laptop reboot | Same as 3–4; local draft (sessionStorage) survives a tab crash; a reboot loses only unsynced seconds, never acknowledged saves | Reconnect screen | — | No | exam-flow: revision ledger == document |
| 6 | Laptop dies; loaner issued | Proctor places a **technical hold**, then **resume with device re-bind**; the first reconnect from the loaner binds it; the old device is refused | "Paused by the invigilator" → continues on loaner | Hold and resume with reasons in the timeline | No (technical hold keeps the epoch) | recovery: loaner re-bind |
| 7 | Exam opened on a second device deliberately | Server-observed **CONCURRENT_SESSION** incident, priority 90; the write is refused; evidence persists even though the write rolls back | "This exam is open on another device — ask the invigilator." | Top of the queue; needs a human decision | Only if a human confirms | exam-flow: device-session mismatch |
| 8 | Tab switch / focus loss / fullscreen exit | Client reports signals; rapid repeats within 2 min group into **one** incident | Nothing punitive | One incident with event count | Only if a human confirms | exam-flow: 3 signals → 1 incident |
| 9 | Camera unplugged / recording gap | **TECHNICAL** incident; a confirm attempt is refused with `TECHNICAL_NOT_COUNTABLE` | "Camera not detected — continue; support has been notified" | Technical queue | Never | exam-flow |
| 10 | Student closes the browser deliberately | Identical to 3; the attempt expires at the server deadline with all acknowledged answers sealed | — | Candidate `EXPIRED`, sealed | No | exam-flow: close seals open attempts |
| 11 | Save after the deadline / after submit | Refused: `DEADLINE_PASSED` / `ATTEMPT_NOT_ACTIVE`; nothing is silently merged | "The exam has ended" | — | No | exam-flow: late write refused |
| 12 | Submit button pressed twice / retried | Same receipt for the same idempotency key; a different key after sealing is `ALREADY_SUBMITTED` | Receipt id + manifest hash | — | No | exam-flow |
| 13 | Clock tampering on the laptop | Readiness `CLOCK_SYNC` fails (> 2 min skew) → fix instruction; the exam uses server time only | "Enable automatic time and retry" | Readiness board shows the check | No | exam-flow: clock check |
| 14 | Wrong or absent secure client | `CLIENT_VERSION` fails (SEB Config Key hash verified server-side); only a Controller can waive it | "Open the exam in the approved exam client" | Blocking check with instruction; waiver needs Controller | No | recovery: SEB hash; exam-flow: waiver |
| 15 | Stolen access token | 10-minute tokens; revoked session family → next request 401; refresh reuse revokes the whole family | Signed out | Audit `auth.refresh_reuse_detected` | n/a | auth |
| 16 | Five validated warnings while saving | Suspension is one transaction holding the attempt lock; a concurrent save either lands before (acknowledged) or is refused — never lost, never phantom | "Paused by the invigilator — your answers are saved" | Priority alert mail + console | Yes (fifth confirmed warning) | exam-flow: race test |
| 17 | Proctor resumes after suspension | New warning epoch at 0; the five historical warnings and all answers remain | Editor resumes | Epoch 2 of N with lifetime count | — | exam-flow |
| 18 | Staff tries to export scripts during the exam | Refused with `EXPORT_LOCKED`; audit row; alert mail to Exam Section and Controller (committed before the refusal) | — | Security alert | n/a | exam-flow |
| 19 | ERP pushes a roster change during the exam | Allocation changes are refused while PRECHECK/LIVE (`EXAM_LOCKED`) | — | — | n/a | exams service rule |
| 20 | Student cannot finish the 15-minute check | Not absent, not failed: `REMEDIATE` with one fix at a time or `REVIEW`; Exam Section sees who and why; the timer has not started | "Need support — this is not counted against you" | Readiness board | No | exam-flow: student B |
